1. What this is

Novig Booth: Get Capped is a Cup photobooth for Novig, a peer to peer prediction market with zero vig. A user snaps a selfie, an AI image model dresses them in their nation's colors with one signature prop, and their trading slip is printed on a shareable 1080x1920 or 1080x1080 poster card with a promo code and a scannable QR. The portrait prints as a real photo, straight photobooth style, no filters.

Open the booth. It runs fully in mock mode with no keys: generation waits two seconds and returns your original photo, so every screen, the loading theater, the slot machine reveal, the confetti, the download, and the share flow can be demoed anywhere.

3. The system

Flow

  1. Landing. GET CAPPED, one button: Run the booth.
  2. Capture. getUserMedia front camera, mirrored preview, pose prompts rotating every 2.3s, Snap it, and an always visible Upload a photo fallback. Camera denial flips upload to the primary action with a friendly note.
  3. Setup. Today's slate (tap a side, get a filled $100 slip), thirteen nation chips, editable slip fields with auto computed to win, LOCKED / CAPPED / COOKED status, Story or Square format.
  4. Generate. POST the photo to /api/generate. Full screen overlay cycles eight lines every 640ms. A minimum 3.2s of theater is enforced even if the model returns faster.
  5. Reveal. The card re-renders 7 times with random nation themes at 120 to 300ms intervals, settles on the chosen nation, and fires a canvas confetti burst. prefers-reduced-motion skips both.
  6. Result. Download PNG, Copy caption, Share (Web Share API with file support when available, text fallback otherwise).

The card, drawn in pure canvas

  • Top block (46% story, 42% square) in the nation color: eyebrow line (matchup and market), the status word in huge outlined strokeText, TO WIN plus the dollar amount at the largest size that fits inside 76px margins, an outlined odds line, then side and stake in small caps. The whole stack height clamps to the block.
  • A diagonal hazard stripe band of rotated rectangles divides the blocks.
  • Bottom block: the portrait as a real photo, cover cropped with a slight bias toward the face. No dither, no duotone, no scanlines, no shading.
  • Vertical rail text on both edges with a soft shadow for legibility over bright photos.
  • A floating dark ticket strip with scallop circles punched out of its top edge via destination-out, a rounded blue N logo, CODE {CODE}, a novig.us subline, and a white QR chip encoding https://novig.us/?code={CODE}.
  • An AI FIT pill badge stamped with the costume seed.

Generation and privacy

  • The API accepts { imageBase64, countryCode, format }, checks mime (jpeg or png) and size (8MB), and calls gemini-2.5-flash-image with a costume prompt that keeps the exact face unchanged and forbids logos, crests, text, and real athletes.
  • No key present: the server waits 2s and echoes the photo back with { mock: true }.
  • No API present at all (static hosting): the browser detects the missing endpoint and runs the same mock locally.
  • Nothing is persisted anywhere, ever. Uploads live in request memory and fall out of scope.

4. How it worked

One coding agent (Claude Code, running remotely against the GitHub repo) built this end to end from a single product brief, in a loop of build, verify with real tools, fix what the verification exposed, and push. The important part was that every claim got checked by machinery, not by eyeballing code:

  • Build gate. npm run build after every change set.
  • Browser truth. Playwright drove the real app headlessly: landing, upload, slate picks, generate, reveal, result, while collecting every console error (the bar was zero).
  • Pixel truth. The rendered card canvas was exported to PNG and visually inspected by the agent. This caught two real bugs no unit test would have found (see pitfalls).
  • QR truth. Card PNGs were decoded with jsQR to prove the QR actually scans to the right URL.
  • Accessibility. Lighthouse ran against the production build (score: 100).
  • Copy rules. Repo wide greps enforced the banned word list and the no em dash rule on every commit.

6. Deploy and test

Vercel (production, real AI fits)

  1. Go to vercel.com/new and import goldytalks/derby-dashboard. No settings needed; the repo is zero config.
  2. Add GEMINI_API_KEY in Project Settings, Environment Variables. Without it the app still works in mock mode.
  3. Optionally set NEXT_PUBLIC_DEFAULT_CODE to change the promo code (default GETCAPPED).

Or from a terminal with the Vercel CLI: vercel, add the key, done.

Static demo (no server, mock only)

bash scripts/build-demo.sh writes a static bundle to docs/. Commit and serve it from any static host or CDN.

Local

npm install then npm run dev. No env vars needed.

What to check when testing

  • Camera capture and upload both produce a card; camera denial shows the upload path.
  • Generate shows at least 3.2s of loading theater, then the slot roll, then confetti.
  • Download produces a correct 1080x1920 or 1080x1080 PNG and the QR scans from a phone.
  • The three slate games load correct $100 slips (to win $120, $160, $69, $650 depending on side).
  • Reduced motion devices get the final card instantly with no roll or confetti.

API (app/api/generate/route.ts)
POST { imageBase64 data URL, countryCode, format }. Validate mime image/jpeg
or image/png and size under 8MB. Call gemini-2.5-flash-image via the
generativelanguage REST API with the photo plus buildPrompt(country), key from

8. Pitfalls the next agent should know

  1. Canvas fonts fail silently. ctx.font keeps its previous value if the assignment is invalid. next/font can emit a fallback list containing an invalid entry (a two word fallback like Arial Black got serialized in a way that broke the whole font-family list), which made every headline render tiny in the wrong face while everything still "worked". Fix: use single word fallbacks in next/font, and in the compositor take only the first family from the CSS variable and append your own known good fallbacks. Verify by rendering and looking at the PNG.
  2. Shrink to fit must clamp both axes. Fitting each line to the card width is not enough; the stacked heights can overflow the color block on the square format. Compute the stack height and scale every size down proportionally when it exceeds the room.
  3. Never resample a QR. Scaling a rendered QR to a fractional size antialiases the modules and can break scanning. Ask the encoder for the module count, pick the largest integer scale that fits the chip, render at exactly that size, draw 1:1, and prove it by decoding the final PNG.
  4. Wait for fonts before canvas. Measure and draw only after document.fonts resolves or the first render uses fallback metrics.
  5. Headless containers have no camera. getUserMedia fails even with fake device flags in some environments. Make the upload path first class and test the denial path; test real capture on a phone.
  6. Static hosts have no API. If you want the demo to run on a CDN, detect the missing endpoint (non JSON response or failed fetch) and run mock mode in the browser.
  7. Copy rules are grep rules. Banned words and punctuation sneak in through comments and docs. Enforce with repo wide greps, not memory.
